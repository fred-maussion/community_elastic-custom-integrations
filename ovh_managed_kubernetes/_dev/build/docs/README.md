# OVHcloud Managed Kubernetes Integration for Elastic

## Overview

The OVHcloud Managed Kubernetes integration enables collection of cluster state, node pool configuration, node lifecycle, and Kubernetes audit log data from [OVHcloud Managed Kubernetes Service (MKS)](https://www.ovhcloud.com/en-gb/public-cloud/kubernetes/) via the OVHcloud REST API.

This integration is designed for organizations running workloads on OVHcloud — Europe's largest cloud provider — and seeking full observability and audit trail coverage without deploying in-cluster agents.

### Compatibility

This integration is compatible with the OVHcloud API v1.0 (EU, CA, and US regions). It requires an OVHcloud service account with OAuth2 `client_credentials` support, available in all OVHcloud regions.

### How it works

The integration uses the CEL input to poll the OVHcloud Management REST API using OAuth2 client credentials authentication. It iterates over all clusters in a given Public Cloud project and collects state snapshots for clusters, node pools, and nodes. The audit stream uses a presigned URL generated by the OVHcloud API to download recent Kubernetes audit events.

## What data does this integration collect?

The OVHcloud Managed Kubernetes integration collects the following data:

* **Cluster** — lifecycle status, Kubernetes version, region, upgrade readiness, and network configuration
* **Node pool** — autoscaling counters (desired/current/available nodes), capacity status, and billing mode
* **Node** — per-node lifecycle status, Kubernetes version, and pool membership
* **Audit** — Kubernetes API server audit events including user identity, resource accessed, verb, and response code

### Supported use cases

- Cluster health monitoring and upgrade readiness alerting
- Autoscaling anomaly detection (underscaled / overscaled pools)
- Node lifecycle tracking (provisioning, errors, upgrades)
- Kubernetes audit trail for security analysis and compliance (GDPR, SOC 2)
- User access auditing: who accessed which Kubernetes resource and when

## What do I need to use this integration?

- An OVHcloud account with a Public Cloud project containing at least one Managed Kubernetes cluster
- An OVHcloud IAM service account with `client_id` and `client_secret` (OAuth2 client credentials)
- The service account must have read access to the Public Cloud project's Kubernetes resources
- Elastic Agent installed on a host with outbound HTTPS access to the OVHcloud API

## How do I deploy this integration?

### Agent-based deployment

Elastic Agent must be installed. For more details, check the Elastic Agent [installation instructions](https://www.elastic.co/guide/en/fleet/current/elastic-agent-installation.html). You can install only one Elastic Agent per host.

### Set up steps in OVHcloud

1. Log in to the [OVHcloud Control Panel](https://www.ovh.com/manager/).
2. Navigate to **IAM** → **Service Accounts** → **Create service account**.
3. Note the `client_id` and `client_secret` generated.
4. Assign the service account read permissions on the Public Cloud project's Kubernetes resources.
5. Note your Public Cloud project ID (`serviceName`) from the project dashboard.

### Set up steps in Kibana

1. In Kibana, go to **Integrations** and search for **OVHcloud Managed Kubernetes**.
2. Click **Add OVHcloud Managed Kubernetes**.
3. Configure the following required settings:
   - **OVHcloud API URL**: Regional API base URL (EU default: `https://eu.api.ovh.com/1.0`)
   - **OVHcloud Project ID**: Your Public Cloud project `serviceName`
   - **OAuth2 Client ID**: Service account `client_id`
   - **OAuth2 Client Secret**: Service account `client_secret`
   - **OAuth2 Token URL**: Regional token endpoint (EU default: `https://www.ovh.com/auth/oauth2/token`)
4. Enable the data streams you want to collect (cluster, nodepool, node, audit).
5. For the **audit** data stream, also provide the **Cluster ID** (`kubeId`) of the target cluster.
6. Save and deploy the policy.

### Validation

After deploying the integration, verify data is flowing:

1. In Kibana **Discover**, filter on `data_stream.dataset: ovh_managed_kubernetes.cluster` to see cluster state events.
2. Check `data_stream.dataset: ovh_managed_kubernetes.audit` for Kubernetes audit events.
3. If no data appears within one polling interval (default 5 minutes), check the Elastic Agent logs.

## Troubleshooting

- No data is being collected: Verify the `service_name` (project ID) is correct and the service account has read permissions on the project's Kubernetes resources.
- Authentication failures (401): Check that `client_id`, `client_secret`, and `token_url` match your OVHcloud region (EU/CA/US).
- Audit stream returns empty: The `kube_id` must be a valid cluster UUID from the target project. Verify it using the OVHcloud API Console or the cluster data stream. Also ensure audit logs are enabled on the cluster (OVH Manager → Kubernetes → cluster → Logs tab) and that the cluster is on the Standard plan or higher.
- Rate limiting (429 responses): Increase the polling interval to 10m or higher for large projects with many clusters.

### API usage

These APIs are used with this integration:

* `GET /cloud/project/{serviceName}/kube` — List all cluster IDs
* `GET /cloud/project/{serviceName}/kube/{kubeId}` — Get cluster details
* `GET /cloud/project/{serviceName}/kube/{kubeId}/nodepool` — List node pools
* `GET /cloud/project/{serviceName}/kube/{kubeId}/node` — List nodes
* `POST /cloud/project/{serviceName}/kube/{kubeId}/log/url` — Generate a temporary URL to download audit logs (kind: `audit`). Requires a Standard plan cluster with audit logs enabled. The returned URL (`get.logs.ovh.com`) is only accessible from within the OVH network.
